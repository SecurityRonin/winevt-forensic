Variants§

§

Verify

Verify the integrity of one or more EVTX files and report tampering indicators.

Checks chunk header checksums, record ID continuity, timestamp monotonicity, and file header consistency.

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§stream: bool

Emit one JSON object per line (NDJSON) instead of a JSON array.

§min_severity: Option<SeverityFilter>

Only report anomalies at or above this severity (info|warning|error|critical).

§

Timeline

Output all events in chronological order as a JSON array.

Each entry contains record_id, timestamp, event_id, level, channel, computer, and provider. Requires an intact or reconstructed EVTX file.

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§stream: bool

Emit one JSON object per line (NDJSON) instead of a pretty-printed array.

§filter_eid: Vec<u32>

Only include events with this event ID (may be repeated for multiple IDs).

§limit: Option<usize>

Return at most N events (applied after –filter-eid and time filters).

§after: Option<String>

Only include events with timestamp >= this value (ISO 8601 UTC string).

§before: Option<String>

Only include events with timestamp < this value (ISO 8601 UTC string).

§

Login

Analyse logon activity from EID 4624 / 4634 / 4647 / 4648 events.

Default: JSON array of reconstructed sessions (logon_id, username, domain, logon_type, ip_address, logon_time, logoff_time, duration_secs).

--graph: JSON object {nodes, edges} — source→target logon graph. --mermaid: Mermaid graph LR diagram (implies –graph output).

Fields

§paths: Vec<PathBuf>

Path(s) to the Security EVTX file(s) or directories (recursive).

§stream: bool

Emit one JSON object per line (NDJSON, sessions mode only).

§logon_type: Option<u32>

Filter sessions by logon type (e.g. 3 = Network, 10 = RemoteInteractive).

§graph: bool

Output the logon source→target graph instead of the session list.

§mermaid: bool

Output a Mermaid graph LR diagram (implies –graph).

§

Frequency

Compute event ID frequency distribution, rare-process analysis, or z-score anomaly detection.

Default (no flags): JSON object with total_events and by_event_id array, sorted ascending (LFO — least-frequent-first) for threat hunting. --by process : JSON array of rare process images (those seen < --threshold times). --anomaly : JSON array of event IDs with |z_score| >= --min-z (default 2.0).

To reorder or cap output, pipe: wt frequency … | jq '.by_event_id | sort_by(.count) | reverse'

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§stream: bool

Emit one JSON object per line (NDJSON) — one EventFrequency per line.

§process: bool

Surface process images from EID 4688 sorted LFO (rare first). Use | head -n N to cap results.

§anomaly: bool

Score event IDs by z-score and return those with |z| >= --min-z.

§min_z: f64

Minimum absolute z-score threshold when --anomaly is active (default 2.0).

§

Repair

Fix bad EVTX checksums and write the repaired file.

Recomputes per-chunk header CRC32 and records-area CRC32. Outputs a JSON report with chunks_checked, chunks_repaired, header_repaired.

Fields

§path: PathBuf

Path to the (possibly corrupt) EVTX file.

§output: PathBuf

Path for the repaired output file.

§

Search

Search all event string values for a substring or regex pattern.

Without --regex: case-insensitive substring match (fast). With --regex: query is compiled as a regular expression.

Exits 1 if matches are found, 0 if none.

Fields

§query: String

Search query (substring or regex pattern).

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§regex: bool

Treat query as a regular expression.

§stream: bool

Emit one JSON object per line (NDJSON).

§

Diff

Diff two EVTX files by record ID. Outputs {"added": [...], "removed": [...]}. Exits 1 if differences found.

Fields

§a: PathBuf

First (baseline) EVTX file.

§b: PathBuf

Second (comparison) EVTX file.

§

ProcessTree

Extract process-creation events and show parent-child relationships. Outputs a JSON array of nodes or a Mermaid diagram with --mermaid.

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (Security or Sysmon).

§mermaid: bool

Emit a Mermaid graph LR diagram instead of JSON.

§

Extract

Extract unique field values, IOCs, PowerShell blocks, WMI events, scheduled tasks, process command lines, lateral movement indicators, RDP sessions, SMB share access, or Defender detections from events.

Modes (mutually exclusive): wt extract <PATH…> <FIELD> — unique field values as {value, count} array wt extract --ioc <PATH…> — IOC scan; exits 1 if IOCs found wt extract --powershell <PATH…> — reassemble EID 4104 script blocks wt extract --wmi <PATH…> — WMI provider/subscription events (EID 5857-5861) wt extract --scheduled-task <PATH…> — scheduled task XML (EID 4698/4702) wt extract --cmdline <PATH…> — process command lines with LOLBin tagging (EID 4688) wt extract --lateral <PATH…> — lateral movement indicators (EID 4648/4769/4776) wt extract --rdp <PATH…> — RDP session events (EID 4778/4779) wt extract --smb <PATH…> — SMB share access events (EID 5140/5145) wt extract --defender <PATH…> — Windows Defender detections (EID 1116/1117/1006)

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (always required).

§field: Option<String>

Field name to extract unique values for (e.g. SubjectUserName). Required unless a mode flag is given.

§ioc: bool

Extract indicators of compromise instead of a named field.

§powershell: bool

Reassemble PowerShell EID 4104 script blocks instead of a named field.

§no_deobfuscate: bool

With --powershell: suppress base64 -EncodedCommand decoding.

§wmi: bool

Extract WMI provider/subscription events (EID 5857/5858/5860/5861).

§scheduled_task: bool

Extract scheduled task XML from EID 4698 (created) and EID 4702 (updated).

§cmdline: bool

Extract EID 4688 process command lines with LOLBin (wscript, mshta, …) tagging.

§lateral: bool

Extract lateral movement indicators (EID 4648/4769/4776).

§rdp: bool

Extract RDP session events (EID 4778/4779).

§smb: bool

Extract SMB share access events (EID 5140/5145).

§defender: bool

Extract Windows Defender detections (EID 1116/1117/1006).

§format: OutputFormat

Output format: json (default) or csv.

§stream: bool

Emit one JSON object per line (NDJSON) instead of a JSON array.

§

ExtractAll

Extract all supported semantic event types and emit a timestamp-sorted unified event list.

Each event object includes a "kind" discriminant field: LateralMovement, RdpSession, SmbAccess, Defender, Wmi, ScheduledTask, or ProcessExecution.

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§stream: bool

Emit one JSON object per line (NDJSON) instead of a JSON array.

§

Info

One-line forensic overview of an EVTX file.

Outputs a JSON object with file, total_events, time_range (first/last), top_event_ids (up to 5 most frequent), integrity_indicators (count), and ioc_count. Ideal for the first look at an unknown file.

Fields

§paths: Vec<PathBuf>

Path(s) to EVTX files or directories (recursive).

§

Report

One-click triage: extract EVTX, verify integrity, run Hayabusa.

Accepts: *.E01 / *.Ex01 — NTFS filesystem extraction; --carved adds full-image carve *.evtx — direct pass-through to Hayabusa directory — all *.evtx files in the tree any other blob — raw carve for ElfChnk magic

Outputs a JSON report with input, evtx_files (name, source, size, integrity_indicators), and an optional hayabusa section.

Fields

§path: PathBuf

Path to the evidence (E01 image, EVTX file, directory, or raw blob).

§carved: bool

For E01 images: also carve the full raw image for deleted/unallocated EVTX data.

§output: Option<PathBuf>

Directory to write extracted EVTX files and Hayabusa output. Defaults to a temporary directory (path printed to stderr).

§hayabusa_bin: Option<PathBuf>

Path to the hayabusa binary. Defaults to hayabusa on PATH.

§min_level: String

Minimum Hayabusa alert level to include (default: low).

§format: String

Output format: json (default) or md (Markdown).
